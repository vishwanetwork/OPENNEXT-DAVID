# Architecture and modularity review — apps/web (branch `refactor/nextjs-monorepo`)

Reviewed 2026-10-26 against commit `4161319`. Scope: `apps/web/src`, `packages/contracts`, `scripts/`,
`Dockerfile`, `docker/`, root and package configs, `docs/`. `legacy/` was read only for the API contract.
No code was changed. All paths below are relative to the repository root unless noted; line numbers refer
to the files as they are on this commit.

Baseline (verified): `pnpm lint` clean, `pnpm typecheck` clean (web and contracts), `pnpm test` in
`apps/web` = 36 files / 188 tests green, `next build` succeeds (41 routes, all dynamic). Root `pnpm test`
**exits 1** because `packages/contracts` has a `test` script but no test files. `prettier --check` fails on
176 of 282 source files. Size: 26,229 non-test lines of TS/TSX in `apps/web/src`, 2,429 lines of tests,
1,429 lines of contracts, 35,350 lines including CSS.

## Executive summary

The foundation is sound: host resolution is a pure, tested function (`src/lib/apps.ts`), the `/api`
pass-through is correct and well-reasoned, every API response is parsed with zod before use (no unparsed
`api.get<T>` calls exist), TypeScript is strict with a single `any`, and the build/lint/test pipeline is
green. What stands between this and a maintainable architecture is the _shape_ of the feature layer, which
reproduces the legacy module system rather than replacing it: the `terminal` feature is a hub with 93 deep
imports from other features and 8 bidirectional import cycles (terminal⇄procurement/billing/instances,
billing⇄procurement); features plug into the shell through 17 `register*` side-effect registries backed by
~25 module-level mutable slots plus a `window.dispatchEvent` bus (six of those registries have no
production caller, so e.g. the terminal's "Contact" actions silently do nothing); server data is copied into a 60-field
zustand "workspace" store typed as `Record<string, unknown>[]` and refreshed by a hand-rolled 30 s loop
that runs _beside_ TanStack Query (three endpoints are fetched by both systems); and 14 of 25 stylesheets
are minified single-line copies. Per-feature consistency is low (api.ts in 6/17 features, hooks.ts in
8/17, two file-naming conventions split by author, five dialog implementations, dead shared UI primitives).
Grade: **C+ / "works, not yet maintainable"** — functional parity was achieved, but the next engineer will
have to reverse-engineer global wiring to add a page. The fixes are mechanical and can be verified
individually; the two that matter most (cut the cycles by extracting a terminal kit; move server records
to React Query) unlock everything else.
